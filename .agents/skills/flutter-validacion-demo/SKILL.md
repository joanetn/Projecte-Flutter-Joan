# Validación de la demo y README

## Cuándo usar

- Revisar si la demo cumple todos los requisitos de `instrucciones.md`.
- Preparar una entrega o una demostración en clase.
- Completar o auditar `README.md`.
- Verificar consistencia visual y reutilización de componentes.

## Procedimiento

1. Leer `instrucciones.md` y convertir cada requisito en una comprobación concreta.
2. Verificar que existen Login, Registro, Principal, Detalle, Nueva reserva, Mis reservas y Perfil/Ajustes.
3. Ejecutar mentalmente o mediante pruebas el recorrido de acceso, navegación inferior, reserva y cierre de sesión.
4. Comprobar que hay al menos seis espacios y dos reservas ficticias visibles.
5. Revisar que el precio de la reserva se actualiza al seleccionar servicios adicionales.
6. Revisar estados, mensajes y etiquetas que indiquen las simulaciones.
7. Comprobar consistencia de colores, tipografía, espaciado, tarjetas, botones y componentes repetidos.
8. Auditar que la estructura de carpetas refleja `domain`, `data` y `ui`, sin exigir nombres exactos.
9. Revisar que `README.md` documenta nombre, autoría, versiones, instalación, ejecución, arquitectura, pantallas, recorrido, acceso, criterios visuales, simulaciones, limitaciones y pendientes.
10. Informar de cada incumplimiento con su ubicación y una corrección concreta; no ocultar fallos ni asumir que una pantalla existe porque aparece en una ruta.

## Resultado esperado

Entregar una lista breve separando:

- Requisitos cumplidos.
- Requisitos incumplidos o parcialmente cumplidos.
- Riesgos de navegación o estado.
- Documentación que falta.
- Verificaciones que no se pudieron ejecutar.
